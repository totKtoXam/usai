# V1 Implementation Plan

## Target

V1 должен дать рабочий deterministic CLI:

```bash
usai init
usai prompt application-usecase
usai rules sources list
usai rules list
usai rules search clean
usai rules install clean-code --size nano --target always
usai rules update
```

## Stack

```text
Language: TypeScript
Runtime: Node.js 24 LTS
CLI framework: commander
Interactive prompts: @inquirer/prompts
Config validation: zod
YAML/frontmatter: yaml + custom frontmatter splitter
Templates: small custom renderer first, avoid complex DSL
Terminal output: picocolors
File discovery: fast-glob
Markdown tooling: prettier first, remark later only if needed
Tests: node:test + golden files
Build: tsup bundled CLI + tsc --noEmit typecheck
Package manager: pnpm
```

Recommendation: start with a small custom renderer for `{{...}}` placeholders. Add a full template engine only if simple replacement becomes insufficient.

## Phase 2: Prompt Generation

Phase 2 deliberately ships in three subphases, one per template mode. Each subphase must leave `usai prompt` in a usable state and reuse the same internal prompt model.

### Phase 2.1: Simple Mode Generation

#### Tasks

- Implement template lookup by name from configured `promptTemplates`.
- Implement template lookup by direct markdown file path.
- Implement template mode detection with Simple Mode enabled first.
- Implement Simple Mode parser:
  - `{{ Question text? }}`
  - `{{key: Question text?}}`
  - `{{key:type: Question text?}}`
  - `{{key:select(option1,option2): Question text?}}`
  - `{{key}}`
- Implement question model:
  - `text`
  - `textarea`
  - `select`
  - `file`
  - `text[]`
  - `file[]`
  - `select[]`
  - `boolean`
  - `number`
- Implement answers file support for non-interactive tests.
- Implement markdown rendering for scalar and list values.
- Implement output file generation.
- Implement explicit `--output` support for writing final prompts into workflow feature folders.
- Return clear "mode is not implemented yet" errors for structured and extended templates until subphases 2.2 and 2.3 are complete.

#### Tests

- Parser unit tests for every placeholder form.
- Golden tests for simple templates.
- Integration test for `usai prompt application-usecase --answers answers.yaml --no-interactive`.
- Integration test for `usai prompt ./draft.md --answers answers.yaml --no-interactive --output ./final.md`.
- Error tests for structured and extended templates before those modes are implemented.

#### Done When

- Developer can create a useful prompt template as one `.md` file.
- The CLI can render exact generated markdown from fixture answers.
- Duplicate placeholders ask once and reuse answers.
- `usai prompt application-usecase` works with the default scaffolded Simple Mode template.
- A generated `draft.md` can be parsed and compiled into `final.md`.

### Phase 2.2: Structured Mode Generation

#### Tasks

- Implement YAML frontmatter parsing for Structured Mode.
- Map frontmatter questions into the same internal `TemplateDefinition` used by Simple Mode.
- Implement required/default validation for frontmatter-defined questions.
- Implement output directory and filename metadata from frontmatter.
- Add structured sample template behind `usai init --with-samples`.

#### Tests

- Golden tests for structured templates.
- Validation tests for required/default fields in frontmatter.
- Output filename metadata tests.
- Regression tests proving Simple Mode behavior remains unchanged.

#### Done When

- Simple and Structured modes compile to the same internal `TemplateDefinition`.
- Simple Mode remains the default recommended path.
- Structured templates can keep metadata and questions in one `.md` file.

### Phase 2.3: Extended Mode Generation

#### Tasks

- Implement external schema loading for Extended Mode.
- Resolve schema paths from configured prompt schema directory.
- Merge template frontmatter metadata with external schema metadata where allowed.
- Implement missing schema, invalid schema and unresolved question errors.
- Add extended sample template and schema behind `usai init --with-samples`.

#### Tests

- Golden tests for extended templates.
- Validation tests for required/default fields from external schema.
- Error tests for missing external schema.
- Error tests for schema/template placeholder mismatch.
- Regression tests proving Simple and Structured modes remain unchanged.

#### Done When

- All three template modes compile to the same internal `TemplateDefinition`.
- Extended Mode supports large reusable schemas without changing the renderer.
- Simple Mode remains the default recommended path.

## V1 Cut Line

Do not include in V1:

- export adapters;
- handoff generator;
- metrics;
- plugin system;
- private source auth;
- rules dependency resolution;
- complex template conditions/loops;
- AI calls.
