# V2 Implementation Plan

## Target

V2 expands `usai` around deterministic adaptation and reporting:

```bash
usai export codex
usai export claude
usai export cursor
usai docs check
usai handoff create
usai metrics collect
```

V2 must not change the identity of the product. `usai` remains a deterministic CLI over markdown/yaml/json assets.

## Phase 8: Export Adapter Core

### Tasks

- Introduce canonical export input model:

```text
ProjectRules
  always
  architectural
  feature
  featureCompletion
  review

ProjectWorkflows
  promptTemplates
  handoffTemplates
  skills
```

- Implement dry-run planning model:

```text
PlannedFileChange
  path
  action
  reason
  contentHash
```

- Implement shared file conflict behavior for exports.
- Add adapter interface:

```text
ExportAdapter
  name
  plan(project)
  render(change)
```

### Done When

- Export dry-run can list planned changes without writing files.
- Adapter core has golden tests independent from a specific agent.

## Phase 9: Codex Export

### Tasks

- Generate/update root `AGENTS.md` as router file.
- Generate `.codex/skills/*/SKILL.md` from selected workflow templates where applicable.
- Generate optional `.codex/skills/*/agents/openai.yaml` interface metadata from deterministic template metadata.
- Preserve existing user-authored sections where feasible, or require explicit overwrite.
- Add dry-run and force handling.

### Done When

- Fixture canonical project exports to exact Codex files.
- Export does not inline every ruleset by default.
- Exported `.codex/skills` are generated views; canonical workflow templates stay in docs/configured template paths.

## Phase 10: Claude Export

### Tasks

- Generate `CLAUDE.md` from canonical rulesets and routing instructions.
- Keep output concise and reviewable.
- Support dry-run and force behavior.

### Done When

- Fixture canonical project exports to exact `CLAUDE.md`.
- Existing modified `CLAUDE.md` is protected from silent overwrite.

## Phase 11: Cursor Export

### Tasks

- Generate `.cursor/rules/*.mdc` files from canonical rulesets.
- Map targets to Cursor rule files.
- Preserve metadata required by Cursor rule format.

### Done When

- Fixture canonical project exports to exact `.mdc` files.
- Rule file names are deterministic.

## Phase 12: Docs Check

### Tasks

- Implement required docs file checks.
- Implement root and layer `AGENTS.md` checks.
- Implement human-only `docs/devs` policy check.
- Add config-driven strict mode.
- Return actionable failures without modifying files.

### Done When

- `usai docs check` passes on a freshly initialized project.
- Missing docs/AGENTS failures list exact paths.
- The command works offline and has integration tests.

## Phase 13: Handoff Packages

### Tasks

- Add handoff templates directory or use built-in default template.
- Implement `usai handoff create`.
- Support interactive and `--answers --no-interactive` modes.
- Render handoff markdown into `docs/devs/handoffs`.
- Support links to generated prompts and ADR files.

### Done When

- Handoff can be generated without AI calls.
- Handoff markdown is understandable without the CLI.

## Phase 14: Metrics Collection

### Tasks

- Implement local project scanner.
- Count:
  - prompt templates;
  - generated prompts;
  - installed rulesets by target;
  - handoffs;
  - ADR files.
- Add output formats:
  - terminal;
  - json;
  - markdown.
- Ensure no telemetry is sent.

### Done When

- `usai metrics collect` works offline.
- JSON and markdown outputs have golden tests.

## Phase 15: Distribution Improvements

### Tasks

- Evaluate standalone binary packaging for Node.js CLI.
- Add platform release artifacts if practical.
- Add Homebrew/Scoop/WinGet plans after binary artifacts stabilize.
- Keep npm/global install available as a simple path.

### Done When

- Users can install `usai` without treating `npx` as the primary UX.
- Binary distribution does not change project file formats.

## V2 Cut Line

Do not include in V2 unless explicitly re-scoped:

- AI execution inside CLI;
- project conversion between agents;
- private marketplace;
- visual workflow designer;
- multi-agent orchestration engine;
- rule conflict auto-resolution;
- semantic search.
