# V2 Test Plan

## Scope

V2 covers export adapters, handoff packages and local metrics. V2 features must still be deterministic and must not introduce AI execution or multi-agent orchestration.

Commands:

```bash
usai export codex
usai export claude
usai export cursor
usai docs check
usai handoff create
usai metrics collect
```

## Export Adapters

### Unit Tests

- Canonical rulesets load by target group.
- Adapter input model is independent from output format.
- Codex adapter maps rules/workflows to `AGENTS.md` and `.codex/skills/*/SKILL.md`.
- Claude adapter maps canonical rules to `CLAUDE.md`.
- Cursor adapter maps canonical rules to `.cursor/rules/*.mdc`.
- Existing file conflict detection works for every adapter.
- Dry-run output lists exactly the files that would change.

### Golden Tests

- Canonical fixture project -> exact Codex export files.
- Canonical fixture project -> exact Claude export files.
- Canonical fixture project -> exact Cursor export files.
- Canonical fixture project with prompt workflow templates -> exact Codex `.codex/skills/*/SKILL.md` exports.
- Export ordering is stable.
- Router files remain concise and do not inline every ruleset unless adapter explicitly requires it.

### Integration Tests

- `usai export codex --dry-run` creates no files and prints planned changes.
- `usai export codex` writes expected files into a temporary project.
- Re-running export without changes is idempotent.
- Existing modified agent file is not overwritten without confirmation or `--force`.
- Unknown export target fails with a helpful list of supported targets.

### Acceptance Checks

- Export does not claim to convert a project between agents.
- Export reads canonical markdown/yaml/json and writes reviewable files.
- Export does not call AI or remote services.

## Docs And Agent Instructions Check

### Unit Tests

- Required file checker reports missing root `AGENTS.md`.
- Layer agent glob checker reports missing configured layer instructions.
- Human-only path checker verifies `docs/devs` guidance.
- Required sections checker reports missing headings with exact path and heading.

### Integration Tests

- `usai docs check` passes in a scaffolded fixture project.
- `usai docs check` fails when root `AGENTS.md` is missing.
- `usai docs check --strict` applies configured project checks.
- Command never writes files.

### Acceptance Checks

- Docs check works offline.
- Failure output is actionable and path-specific.
- V2 does not require language-specific namespace maps unless project config explicitly opts in.

## Handoff Packages

### Unit Tests

- Handoff template renders required sections in stable order.
- Empty optional sections render predictably.
- Filename generation is deterministic and readable.
- Links to generated prompts and ADR files are rendered as relative markdown links.

### Golden Tests

- Answers fixture -> exact handoff markdown.
- Handoff with prompt links -> exact markdown.
- Handoff with risk and next-step lists -> exact markdown.

### Integration Tests

- `usai handoff create --answers handoff.yaml --no-interactive` writes a handoff file.
- Missing required handoff summary fails clearly.
- Existing handoff filename conflict is handled without silent overwrite.

### Acceptance Checks

- Handoff file can be understood without `usai`.
- Handoff content is commit-friendly markdown.
- V2 does not automatically scrape Codex/Claude/Cursor session history.

## Metrics Collection

### Unit Tests

- Project scanner counts generated prompts, templates, installed rulesets, handoffs and ADR files.
- Scanner ignores configured generated/cache directories where appropriate.
- Metrics output model can render terminal, markdown and JSON formats.
- Sensitive file content is not included by default.

### Golden Tests

- Fixture project -> exact JSON metrics.
- Fixture project -> exact markdown metrics report.

### Integration Tests

- `usai metrics collect` prints terminal summary.
- `usai metrics collect --format json --output metrics.json` writes JSON.
- `usai metrics collect --format markdown --output docs/devs/metrics.md` writes markdown.
- Empty project returns zero counts without failing.

### Acceptance Checks

- Metrics run offline.
- No telemetry is sent.
- Metrics do not evaluate developer productivity or AI quality.

## V2 Regression Requirements

Every V2 command must preserve V1 guarantees:

- Config resolution priority remains unchanged.
- Commands are deterministic.
- Project files are not overwritten silently.
- Generated outputs are reviewable through git diff.
- No AI calls are introduced.

## V2 Manual Smoke Matrix

Run on:

```text
Windows x64
Linux x64
macOS arm64
```

Smoke flow:

```bash
usai export codex --dry-run
usai export claude --dry-run
usai export cursor --dry-run
usai docs check
usai handoff create --answers handoff.yaml --no-interactive
```

Expected:

- Dry-run export changes no files.
- Generated handoff is readable markdown.
- Metrics output contains only local project information.
